## Proposed sequence and boundaries

Strengthen server-derived identity and tenant-scoped generic append idempotency on the real admission path first. Reuse the existing packaged SQLite bus. Prefer PostgreSQL as future operational authority when independent tenants/writers, a recovery need or a measured workload justifies the operating cost. Evaluate Cloud SQL hosting separately from logical schema choice. Firestore supports serializable transactions and remains a viable alternative if its exact edition/API and operating effort fit better. No arbitrary traffic/latency threshold or cloud purchase is approved.

Mother publishes bounded policy/routing proposals and receives child-computed, fixed-schema health summaries pushed by children. It holds no general child-content read credential and cannot issue itself universal child authority. Child services enforce local ceilings and require explicit child authorization for broader access/actions. A compromised control plane can still harm availability; this proposal does not claim total control-plane compromise containment.

Enroll each child publisher under a separately authenticated workload principal and bind that principal to its authorized child on the receiving server. Authenticate the transport/token and reject claimed identities that contradict this binding. Persist the accepted enrollment epoch and increasing sequence per child; check credential/report expiry and bounded report age. Duplicate reports must not refresh health freshness, and an expired, old-epoch or wrong-child report must not alter routing. Re-enrollment advances the server-authorized epoch and revokes the former credential. Negative tests cover forged child identity, revoked enrollment and stale/replayed health, including receiver restart.

Human identity, workspace membership, worker identity, Cloud SQL connect/login IAM, SQL table/view grants and external-action capabilities are separate boundaries. Client-supplied selectors do not confer membership. A pooled Postgres runtime uses tenant composite keys and RLS as defense in depth, with non-owner/non-BYPASSRLS roles and checked transaction-local context. This does not contain a compromised all-tenant runtime that can set arbitrary context. FORCE RLS does not constrain superusers/BYPASSRLS or sanitize pooled connections. A zero-row UPDATE may be normal SQL success; admission code must check affected rows before outbox dispatch.

Enrollment maps a verified human identity-provider subject or separately provisioned worker credential to a server-owned principal and explicit tenant/role membership. Validate issuer, audience, signature and expiry as appropriate to the chosen mechanism; do not treat a shared internal bus secret as a client identity. Give clients/workers individually revocable credentials and recheck current membership at admission and dispatch. Actor fields cannot set identity; resource selectors are only requests and must be authorized against the authenticated principal. Rotation, revocation and suspended-membership tests are part of the real admission-path integration.

One transaction durably reserves tenant-scoped request ID plus payload digest, budget, job and outbox. The same tenant/request ID with the same digest returns the original durable receipt, creating no additional reservation, job or outbox; a different digest conflicts. Provider effects occur outside retryable transactions. Persist a stable external-effect key bound to tenant, action, destination and accepted payload across transport retries; keep individual attempt IDs and outcomes separately. Recheck current capability, membership, fence and destination before an external action. Each provider needs a documented idempotency/lookup contract, including retention limits. If acceptance may have occurred and neither safe replay nor authoritative lookup can resolve it, put the item on manual hold without automatic retry or invented completion. Test timeout after provider acceptance and worker restart before enabling retries. No database can promise exactly-once effects in an unrelated provider by itself.

After a separately accepted migration, Sheets may be a sanitized read-only projection. Inventory actual writers and consumers. Preserve the canonical ten A:J cells; blank K:L are read-side padding, never write columns. Preserve and quarantine any row with non-blank cells past J rather than silently truncating or reinterpreting it, as required by `docs/COMMS-PROTOCOL.md`. Assign tenant ownership explicitly or quarantine it. Rehearse snapshot/import/restore with source IDs, values, digests and duplicate dispositions.

Cutover requires an enforceable source-side write epoch/fence, a durable snapshot watermark, and drain/acknowledgement of in-flight writes and effects. Reconcile or quarantine every post-watermark append or edit and record the final source-to-destination mapping before enabling one new writer. Legacy Sheets writers may not enforce an epoch: inventory and quiesce or disable every write authority and command consumer, prove the source frozen, and capture the final verified delta; if that cannot be established, do not cut over. Row position or timestamps alone are not an immutable watermark. Record the destination's first-write watermark and reconcile all later writes and uncertain effects before any rollback; also check the old source for late divergence. A stale Sheet URL is not a recovery protocol. Regional Cloud SQL HA is not multi-region disaster recovery.
