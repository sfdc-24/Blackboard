## Gemini's reply (verbatim)

Here is the architectural review and build plan to deliver the real-time "blackboarding" experience, based on the logs and the owner's feedback.

### 1. Verdict on the Core
**Decision:** Adopt Grok's proposal: **Gemini Live as the single conversational core**, merged with the **studio-controller SSE loop** for visual artifacts. 
**Cut completely:** Evolving the existing conference chair Python loop. 

**Why:** The existing chair's latency (2-5s for Claude-to-voice) destroys conversational flow. Stitching text-based LLMs to separate TTS engines will never feel like a natural working session. Gemini Live natively processes and generates audio in <1 second (0.9s proven in your logs) and natively handles barge-in without manual VAD cancellation hacks. By making Gemini the only "voice" that speaks (acting as the host and proxy for the other agents), you eliminate the robotic turn-taking, the 15-second hard cutoffs (which ruined the 10:07 interaction), and the 2.5s idle advances. 

### 2. Architecture Diagram

```mermaid

    Browser[Browser / New Conference Page]
    
    subgraph GCP Cloud Run
        Studio[Studio-Controller SSE]
        Gemini[Gemini Live Core API]

        Grok[Grok Worker: Strategy]
    end

    subgraph Datastores
        Redis[(Memorystore Redis)]

    Browser -- WebRTC Audio (Voice & Barge-in) --> Gemini
    Browser <-- SSE Artifacts/Patches -- Studio
    
    Gemini -- Tool: write_to_lane --> Redis
    Gemini -- Tool: read_live_state --> Redis
    
    Redis -- Stream: v1:conf:lanes --> Claude

    Claude -- Writes patches (CAS) --> Redis
    Grok -- Writes strategic notes --> Redis
    
    Redis -- Pub/Sub updates --> Studio

    Board -- async logging --> Studio
```

**Key Redis Structures:**
*   `v1:conf:state` (Hash): Current active topic, agenda index, and schema version.
*   `v1:conf:lanes` (Stream): Tasks pushed by Gemini for Claude/Grok/Codex to compute asynchronously.
*   `v1:conf:events` (Stream): The artifact patches (DOM/Canvas updates) generated by lanes, consumed by Studio-Controller for SSE broadcast.

### 3. Turn-taking and Latency
*   **Concrete Targets:** First audio < 0.9s. Max silence before host prompt: 4s. Barge-in latency: < 0.5s.
*   **Removing the 15s Cutoffs:** Delete `MAX_REPLY_SECONDS`. Instead, rely on native WebRTC barge-in (the owner can interrupt anytime) and instruct Gemini in the system prompt: *"Keep all responses under 3 sentences unless the owner explicitly asks you to elaborate or explain a complex architecture."*
*   **How Lanes Report Back:** Lanes (Claude/Grok) **do not speak**. They process tasks on Redis streams and output visual artifact patches or text summaries back to Redis. Studio-controller pushes a silent UI notification (e.g., "Claude updated the diagram"). Gemini uses a `check_lane_status` tool to see the update and vocalizes it naturally: *"Claude just pushed the new data model to the board, what do you think of the caching layer?"*

### 4. Context: Live State vs. OKF
*   **The Problem:** Baking 6,000 characters of OKF markdown into the image blindfolded the agents. 
*   **The Fix:** 
    *   **OKF (Background Knowledge):** OKF is loaded on session start. Do not append it to every turn. Pass it as the initial `system_instruction` to Gemini and the background workers. It defines the rules, not the current state.
    *   **Redis (Live State):** Every turn, Gemini must have access to what is actually on the screen. Do this by providing Gemini a tool `get_canvas_snapshot`. When the owner asks "What's wrong with this diagram?", Gemini calls the tool, which reads `v1:conf:state` from Redis (returning a lightweight JSON representation of the diagram, < 2,000 tokens), and then answers.

### 5. The New Conference Experience Page (v1)
*   **Minimum First Version:** Owner-only IAP login. A split-screen UI: left side is a blank visual canvas, right side is a mic button. The session starts instantly with Gemini asking: *"What are we working on today?"* As the owner speaks, Gemini delegates diagramming to Claude, which visually populates the left-side canvas.
*   **Reuse Verbatim (from Start Conversation):** The WebRTC -> POST/SSE loop, the Canvas DOM renderer, the artifact patch schema (`events.schema.json`), and the end-of-session PDF email generator.
*   **Defer for later:** Guest email/OTP sign-in, multi-room routing, and complex OKF git-writeback.

### 6. Build Order (Next 48 Hours)
**Phase 1: The Core Spike (Hours 1-12)**
*   *Action:* Stand up Gemini Live WebRTC connection with a single tool (`write_redis_stream`).
*   *Acceptance Scorecard:* Audio latency < 1.0s. Native barge-in successfully stops audio. Tool call successfully writes a dummy string to Redis `v1:conf:lanes`.

**Phase 2: Visual Canvas Port (Hours 13-24)**
*   *Action:* Clone the "Start Conversation" UI behind the IAP owner route. Hook up the SSE stream to listen to Redis `v1:conf:events`.
*   *Acceptance Scorecard:* Manual CLI write to Redis `v1:conf:events` renders a box on the browser canvas in < 0.5s.

**Phase 3: Lane Workers (Hours 25-36)**
*   *Action:* Deploy Claude worker to listen to `v1:conf:lanes`, generate an `events.schema.json` patch, and write to `v1:conf:events`.
*   *Acceptance Scorecard:* Gemini asks for a diagram -> writes to lane -> Claude processes -> UI updates. End-to-end latency < 8s for visual generation.

**Phase 4: Context & Polish (Hours 37-48)**
*   *Action:* Inject distilled OKF into system prompts. Enable PDF generation on session end.
*   *Acceptance Scorecard:* Gemini correctly answers a question based on OKF rules. PDF is delivered to the owner's email upon closing the browser tab.

### 7. Top 5 Failure Modes & Mitigations

1.  **Failure:** **Budget Exhaustion (CAD 25/day limit).** Multimodal real-time streaming is token-heavy.
    *   *Mitigation:* Hard-cap sessions to 15 minutes. Use `gemini-1.5-flash-realtime` instead of Pro. Throttle lane worker triggers (max 1 diagram update per 30 seconds).
2.  **Failure:** **Lane Workers Hallucinate Broken JSON.** Claude outputs invalid artifact patches, breaking the studio canvas.
    *   *Mitigation:* Strict JSON schema validation in the Cloud Run worker before executing the CAS commit to Redis. Drop invalid patches and write an error back to the lane stream for Gemini to handle.
3.  **Failure:** **Audio Echo / VAD looping.** The mic picks up Gemini's own voice from the speakers and causes infinite hallucination loops.
    *   *Mitigation:* Ensure WebRTC echo cancellation is strictly enforced in the browser client. If unresolved, implement a soft push-to-talk (PTT) spacebar override for the owner.
4.  **Failure:** **Context Desync.** Gemini speaks about a diagram that Claude hasn't finished rendering yet.
    *   *Mitigation:* Gemini must rely on SSE confirmation. Do not let Gemini assume a tool call worked. Gemini must wait for a system message or use a `read_state` tool to confirm the UI reflects the change before saying "There, I've drawn the architecture."
5.  **Failure:** **Redis Race Conditions.** Multiple agents trying to update `v1:conf:state` simultaneously.
    *   *Mitigation:* Strict Compare-and-Swap (CAS) optimistic locking using the `epoch` and `generation` fields already defined in your `events.schema.json`. If a worker's patch fails CAS, it drops the update.
